FlatRadar — 使用指南

跨平台监控七个平台的房源并实时通知，支持 Holland2Stay 自动预订和 Plaza 自动应征。

快速开始

1 Docker（推荐，适合 VPS）

cp .env.example .env && mkdir -p data logs logs/caddy
# 编辑 Caddyfile，将 your.domain.com 替换为实际域名
# 编辑 .env，设置 WEB_PASSWORD、PUBLIC_BASE_URL 和 SESSION_COOKIE_SECURE=true
docker compose up -d

在浏览器中访问 https://your.domain.com，登录后于仪表盘点击启动监控。登录用户名默认为 admin。

完整部署步骤与邮件、代理等配置见项目文档。

若暂无域名，可先在本机试运行：docker compose -f docker-compose.yml -f docker-compose.local.yml up -d h2s，随后访问 http://127.0.0.1:8088。该方式不启用 HTTPS 与登录鉴权，仅限本机使用。

2 macOS

自 Releases 下载最新的 .dmg，拖入 Applications 目录后双击启动。

3 Windows

自 Releases 下载最新的 .zip，解压后双击 flatradar.exe 运行。

4 iOS / Android App

iOS：在 App Store 下载，为原生 SwiftUI 客户端。

Android：下载 Android App（.apk），为 Kotlin + Compose 客户端，采用 FCM 推送。

5 从源码运行

pip install -r requirements.txt
python -m cloakbrowser install
cp .env.example .env
python web.py      # 面板
python monitor.py  # 抓取循环，需另开终端

在浏览器中访问 http://127.0.0.1:8088。web.py 与 monitor.py 是两个互相独立的进程，仅运行前者将得到一个不会更新数据的面板。

支持平台

FlatRadar 支持以下七个平台，房源上的平台标签标识其来源。各平台的实际覆盖范围以设置和平台数据为准。

平台覆盖范围数据粒度自动预订
Holland2Stay (H2S)可配置的荷兰城市单元级（具体房号、租金、面积）自动预订，需手动付款
OurDomain (OD)Amsterdam（Diemen 与 South-East）单元级（#6045、面积、楼层、朝向）❌ 仅通知
OurCampus (OC)Amsterdam Diemen（1 栋）单元级（同 OurDomain）❌ 仅通知
Xior (XR)荷兰 30 栋楼，分布于 14 个城市单元级（M1.30.53、面积、租金、押金）❌ 仅通知
Magis (MG)5 个城市共 17 栋楼，Eindhoven 占 9 栋单元级（租金、面积、楼层、能耗标签）❌ 仅通知
Student Experience (SE)Amsterdam 与 Leiden户型级（起价与面积范围）仅通知
Plaza (PZ)荷兰多个城市房源级（租金、面积、楼层）自动应征，默认关闭
提示：在设置 → 平台中启用或禁用平台，在设置 → 城市中选择需监控的城市或楼盘。

Web 面板概览

Web 面板是系统的控制中心，全部功能均可自左侧栏进入。

仪表盘

提供总览信息：数据库中的房源总数、当日新增、当日变更与最近一次抓取时间，并列出最新房源及近 48 小时内的状态变更。房源带有来源平台标签。

点击启动监控即开始抓取，运行期间状态圆点显示为绿色。

房源列表

用于浏览数据库中的全部房源，支持按状态、城市、平台、户型、最高租金、最小面积、合同类型、能耗等级等条件筛选。点击房源名称即跳转至源平台的详情页。

状态旁的「推测」标记表示状态由系统推断，而非平台上报。对于从已完整检查的房源列表中消失的房源，默认分别在消失 30 分钟和 2 小时后推断为 Reserved 和 Occupied；阈值可配置，抓取不完整时不会据此推断。房源重新出现时标记会清除。做出决定前请以平台页面为准。

地图

地图使用 Google Maps，与房源列表共用筛选条件、平台分组和搜索范围。单套房源显示价格，同一位置的多套房源显示数量；点击标记可在右侧查看房源和完整详情，未定位的房源单独列出。地图默认显示近期记录，也可切换至全部记录。底图需配置 GOOGLE_MAPS_API_KEY；未配置或加载失败时，右侧列表和详情仍可使用。

地图只显示近期还被抓到过的房源，默认十四天，可在「设置」页的 「地图显示范围」里改，填 0 显示全部。已入住是状态收敛的终态，那些记录会长期留在 数据库里；不加这道限制，几个月前就从平台上撤下的单元仍然会钉在图上。

坐标由监控进程自动解析并缓存，无需手动操作；新抓到的房源通常在半小时内出现在图上。 管理员也可以在地图页手动触发一次，用于排查。

日历

按月份显示入住日期，可按城市与平台筛选。

统计

可在 7 / 30 / 90 天之间切换，展示新增趋势、变更趋势，以及城市、状态、平台分布、租金分布与上线时段分布。

通知推送

进入用户管理，点击目标用户，选择通知渠道。

Telegram 跨平台

  1. 在 @BotFather 处创建 bot，复制其 token
  2. 向该 bot 发送一条任意消息
  3. 访问 https://api.telegram.org/bot<TOKEN>/getUpdates 以获取 Chat ID
  4. 将 Bot Token 与 Chat ID 填入面板

Email 跨平台

有两种方式，默认是第一种。

一、由服务代发（默认）。只填收件邮箱即可，不需要 SMTP 服务器。 填好后会收到一封确认邮件，点击其中的链接完成验证之后才会开始投递—— 这道确认用于防止把别人的邮箱填进来。验证状态在用户配置页可以看到，也可以重发确认邮件。

自部署时，管理员须先配置共享邮件服务和公开访问地址；未配置时可使用自建 SMTP。

二、自建 SMTP。把邮件模式改为自定义，再填服务器信息。常见服务商如下：

服务商SMTP 地址端口加密
Gmailsmtp.gmail.com587STARTTLS
Outlooksmtp.office365.com587STARTTLS

账号已开启两步验证时，须使用应用专用密码。自建 SMTP 不需要邮箱验证， 投递结果由你自己的服务器负责。

iMessage 仅 macOS

填入收件人手机号（如 +31612345678）或 Apple ID 邮箱。该渠道仅在 macOS 上、且 Messages.app 已登录时可用。

WhatsApp Twilio 付费

需具备 Twilio 账号，并填入 Account SID、Auth Token 及 whatsapp:+... 格式的号码。

iOS 推送通知

使用 FlatRadar iOS App 时，APNs 推送自动发送，并按设备语言在中英文之间自动选择。

Android 推送通知

使用 FlatRadar Android App 时，FCM 推送自动发送，同样支持中英双语。

设备推送与「通知开关」的关系

用户配置里那个通知开关管住全部渠道，设备推送也在内。关掉它， 手机就不再收到推送。

在 App 里授权推送权限并登录，会自动打开这个开关——在手机上同意接收，就是同意接收， 不必再去面板点一次。此后你在面板上关掉它，才是真的关掉。

提示：点击发送测试通知可对各渠道逐一验证，设备推送也在测试范围内。 面板首页会在「你当前收不到任何通知」时给出一张清单，指明缺的是哪一步。

自动预订与应征

进入用户管理，点击目标用户，选择自动预订。

自动预订需要启用用户通知，并至少有一种可用的接收方式。预订过滤条件独立于通知过滤条件；空条件表示不限制。

工作流程

当 Holland2Stay 房源转为可预订且满足所设条件时，系统依次执行：

  1. 登录 Holland2Stay 账号
  2. 创建购物车并提交占房请求
  3. 提交订单（placeOrder）
  4. 生成直达付款的 URL（idealCheckOut）
  5. 即时发送付款链接

系统不会自动完成付款，收到链接后须自行支付。

如果预订结果不明确，该 Holland2Stay 账号的自动预订会暂停。请先登录 Holland2Stay 核实订单或预留、按需付款或取消，再在用户设置中点击已核实，恢复自动预订。后台任务仍在运行时无法解除保护；如已卡住，请先停止监控。

Plaza 可自动提交符合条件的应征；需要提供 Plaza 用户名与密码，并单独开启默认关闭的 Plaza 自动应征开关。提交即生效，不保证获得房源。

如果 Plaza 应征结果不明确，请登录 Plaza 核实“我的应征”，再在用户设置中选择已核实，恢复该房源应征。核实前只暂停该账号对该房源的自动应征；其他房源不受影响。后台应征仍在运行时不能解除保护。

OurDomain、OurCampus、Xior、Magis 与 Student Experience 目前仅通知、不自动预订。

配置项

  • 启用自动预订：总开关
  • 试运行模式：建议先行启用，验证提交前的部分步骤，不实际提交订单或应征；通过不代表正式提交一定成功
  • Holland2Stay 账号邮箱与密码
  • Plaza 用户名与密码及自动应征开关：使用 Plaza 自动应征时配置，开关默认关闭
  • 支付方式：iDEAL（默认）、Visa 或 Mastercard
  • 预订过滤条件：与通知条件分别设置，按自己的预订要求填写
注意：请在试运行模式下确认流程无误后再将其关闭，以免误提交订单。

通知过滤条件

进入用户管理，点击目标用户，选择过滤条件。

条件示例适用平台说明
最高租金€1200全部仅推送不高于 €1200/月的房源。各平台价格口径不同，见下方
最小面积25 m²全部仅推送不小于 25 m² 的房源
最低楼层1Holland2Stay、OurDomain、OurCampus、Magis、Plaza排除底层（0 层）
城市Eindhoven, Amsterdam全部可多选，满足任一项即匹配
平台H2S, OD全部可多选，仅推送所选平台的房源
租客要求student onlyMagis 除外可多选，满足任一项即匹配
户型Studio, 1Xior 除外可多选，满足任一项即匹配
入住人数SingleHolland2Stay、OurDomain、OurCampus可多选，满足任一项即匹配
装修类型FurnishedHolland2Stay、OurDomain、Xior、Magis可多选，满足任一项即匹配
合同类型Indefinite仅 Holland2Stay仅推送长租房源，排除短租
最低能耗B仅 Holland2Stay、Magis仅推送不低于该等级的房源
街区Strijp, Centrum仅 Holland2Stay可多选，选项随所选城市变化
供应形式Rent仅 Holland2Stay可多选，用于区分出租与其他挂牌形式

各项条件须同时满足才会推送；留空表示该项不作限制。

「适用平台」一列很重要：某个平台不提供该字段时，这个条件对它整体跳过， 而不是把它的房源全部排除。也就是说，勾了「最低能耗 B」并不意味着推来的都是 B 级—— Xior、OurDomain、OurCampus 的房源根本没参与这一关。面板的筛选项旁也标着同样的范围。

对于支持该条件的平台，个别房源仍可能缺少相应数据；不同字段的缺失处理不同，筛选结果不能替代对平台页面的核实。

租金的口径

各平台的价格口径不同，设置「最高租金」之前请先看清楚：

平台面板与通知里显示的价格
Holland2Stay到手价：含服务费与水电预付
Xior到手价：基础租金加上该楼盘登记的月度预付费用
OurDomain基础租金，服务费另计
OurCampus基础租金，服务费另计
Magis到手价：基础租金加上每条房源自己印着的服务费
Plaza平台上报的总租金；有净租金时会另行显示
Student Experience户型的起价，不一定是某一间的实际租金

OurDomain 与 OurCampus 的服务费按户型变化，而上游不提供单元与户型的对应关系，因此无法合成到手价。 面板上这类房源的价格右上角带一个星号，悬停可看到该楼盘服务费的区间；通知里的租金行 也会附上同样的说明。

这对筛选意味着什么：同一个租金上限，在 Holland2Stay 与 Xior 上过滤的是 你实际要付的钱，在 OurDomain 与 OurCampus 上过滤的是不含服务费的部分。给后两者留出余量， 或用平台条件把它们分开处理。

平台与城市

七个平台均可分别启用或禁用，并可选择其城市或楼盘；Xior 的楼盘按城市分组显示。

保存后会请求监控进程重新加载运行配置；设置页显示是否已应用和是否被覆盖。部署参数、密钥和高级超时配置仍需重启相关进程。

常见问题

监控显示为「已停止」

在仪表盘点击启动监控。若仍无法启动，请查阅日志查看器或执行 docker compose logs h2s。

没有房源出现

  • 确认设置中已选择城市或楼盘
  • 确认相应平台已启用
  • 查阅错误日志，检查是否存在 403 或网络错误

收不到通知

先看面板首页。「你现在收不到通知」的时候那里会出现一张清单，直接指明缺的是哪一步； 清单消失就说明这条链路是通的。手动排查按下面的顺序：

  • 该用户已启用，且通知开关是开着的——这个开关同时管住邮件、 Telegram 等外部渠道和手机推送，关着的时候一条都不会发
  • 至少有一条接收方式：配了有效凭据的外部渠道，或者登录着 App 的手机。 只用 App 的话，「通知渠道」一栏是空的属于正常
  • 用邮件且是默认的代发模式时，确认收件邮箱已完成验证——未验证不投递
  • 点击发送测试通知逐一排查，结果按渠道分别列出，设备推送也在内
面板上的通知列表不能用来判断这件事。那是全站流水，不分用户、不按你的过滤条件 筛选；里面有内容不代表你配好了。只有上面这条链路通了，才会按你的条件推给你。

被 Cloudflare 返回 403

  1. 查看日志，确认受影响的平台和具体错误；403 不一定都由同一种原因造成
  2. 检查当前网络和已配置代理是否可用；如果出口被限制，可按部署说明配置代理
  3. 等待平台冷却后再观察恢复情况，持续失败时检查平台状态和日志

房源状态与平台页面不一致

先检查状态旁是否带有「推测」标记。带该标记的状态由系统依据房源从列表中消失的时长推断得出，并非平台上报，因此可能与平台页面存在出入。做出决定前请以平台页面为准。

实用提示：日志查看器（管理员 → 侧栏终端图标）支持在 Monitor Log 与 Errors Log 之间切换，并提供关键词搜索、行号显示与级别着色，是排查问题的首选入口。
