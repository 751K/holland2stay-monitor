FlatRadar 监控荷兰七个租房平台，把符合你条件的新房源推送给你，还能替你预订 Holland2Stay 的房子、在 Plaza 自动提交申请。

开始使用

直接用 flatradar.app

打开 flatradar.app，不注册也能浏览全部房源。想收到提醒，点登录 / 注册：未注册的用户名会自动创建账户。注册后会进入账号设置，在那里设好筛选条件和接收方式。

iOS 与 Android App

iOS：App Store。Android：下载 .apk。用同一个账号登录并允许通知，就能收到推送，不需要其他设置。

自己部署一份

FlatRadar 仅限个人、非商业使用。自己部署的版本会在名称后显示自部署版本，运行与后果由部署者负责。

在自己电脑上用（只给自己收提醒）：装好 Python 3.11+，然后

git clone https://github.com/751K/holland2stay-monitor.git
cd holland2stay-monitor
pip install -r requirements.txt
python launcher.py

第一次会下载一次浏览器内核，之后面板在 http://127.0.0.1:8088 打开，监控自动启动。到用户里给自己建一个用户、启用通知渠道（Telegram 或自己的 SMTP 邮箱）并发一条测试即可。关掉终端就同时停止。这种模式没有密码，只能在自己电脑上用；macOS 上抓取时可能弹出一个浏览器窗口，保持打开即可。

公网部署（给别人用，推荐 Docker）：

cp .env.example .env && mkdir -p data logs logs/caddy
# Caddyfile：把 your.domain.com 换成你的域名
# .env：设置 WEB_PASSWORD、PUBLIC_BASE_URL 和 SESSION_COOKIE_SECURE=true
docker compose up -d

打开 https://your.domain.com，用 admin 登录，到管理后台 → 系统信息点启动监控。部署、邮件与代理设置见项目文档。

macOS / Windows 安装包：从 Releases 下载 .dmg 或 .zip 运行，浏览器会自动打开。

支持的平台

每条房源都会标出来自哪个平台。实际覆盖范围取决于你所用站点的设置，以及各平台公开的数据。

平台覆盖范围数据粒度预订
Holland2Stay可选的荷兰城市单套：房号、租金、面积自动预订，付款需本人完成
OurDomain阿姆斯特丹（Diemen、South-East）单套：房号、面积、楼层、朝向仅通知
OurCampus阿姆斯特丹 Diemen（一栋楼）单套，同 OurDomain仅通知
Xior14 个城市的 30 栋楼单套：房号、面积、租金、押金仅通知
Magis5 个城市的 17 栋楼，其中 9 栋在埃因霍温单套：租金、面积、楼层、能耗标签仅通知

Plaza荷兰多个城市房源：租金、面积、楼层自动申请，默认关闭

房源收件箱

首页是一个房源收件箱：左边是侧栏，中间是房源列表，右边是选中房源的详情。手机上点左上角的菜单按钮打开侧栏。

  • 我的匹配 / 全部房源：侧栏顶部的切换。「我的匹配」按你保存的筛选条件显示；「全部房源」显示所有房源，其中符合你条件的会带匹配标记。
  • 可预订、未读房源和各平台用来缩小列表。打开一条房源就会标为已读。
  • 搜索会查房源名、城市和平台。标题旁的调整筛选会带你去改筛选条件（没登录时则是临时筛选）。
  • 详情里有价格、状态、房屋信息和原网页链接。行动前请以平台页面为准。

带系统推测标记的状态是 FlatRadar 推算的，不是平台给的。房源从完整检查过的列表里消失后，默认 30 分钟推测为「已预留」，2 小时推测为「已入住」。抓取不完整时不会做这种推测；房源重新出现，标记就会消失。

列表、日历和地图

列表上方的三个标签用三种方式看同一批房源。日历按入住日期排；入住日期未定的房源单独列出。地图上单套房源显示价格，同一栋楼有多套时显示数量，点标记即可查看。地图只显示近期还能看到的房源（默认 14 天），也可以切换到全部记录。坐标由监控自动解析，新房源通常半小时内出现在地图上。

统计

最近 7、30、90 天的图表：新增房源、状态变化、城市、平台、状态和租金分布。统计范围跟着侧栏走：「我的匹配」只统计你的匹配，「全部房源」统计全部。

通知

进入账号设置 → 通知。最上面的通知开关管所有渠道，包括 App 推送：关掉之后什么都不会发。然后至少开一种接收方式。

App 推送

在 iOS 或 Android App 里用你的账号登录并允许通知，就完成了；App 还会顺便把通知开关打开。推送跟随手机语言显示中文或英文。

Telegram

  1. 找 @BotFather 创建一个机器人，复制它的 token。
  2. 给你的新机器人发一条任意消息。
  3. 打开 https://api.telegram.org/bot<TOKEN>/getUpdates，找到你的 chat ID。
  4. 在 Telegram 一项里填入 token 和 chat ID。

邮件

由 FlatRadar 发信（默认）：填写邮箱，点确认邮件里的链接。确认之前不会投递，这样别人没法替你订阅。自部署的站点需要管理员先配置共用的发信服务，否则请用自己的 SMTP 服务器。

自己的 SMTP 服务器（管理员）：把邮件模式切换为自定义，填写服务器信息。开了两步验证的邮箱要用应用专用密码。

服务商SMTP 主机端口加密
Gmailsmtp.gmail.com587STARTTLS
Outlooksmtp.office365.com587STARTTLS

WhatsApp 与 iMessage

WhatsApp 通过付费的 Twilio 账号发送：需要 Account SID、Auth Token 和 whatsapp:+… 号码。iMessage 只在 FlatRadar 本身运行在已登录「信息」的 Mac 上时可用。

点发送测试通知检查每个渠道，包括 App 推送，结果会逐个列出。账号收不到任何通知时，账号设置页会显示一张清单，指出缺的是哪一步。

筛选条件

进入账号设置 → 房源条件。收件箱和通知用的是同一套条件。所有条件同时满足才算匹配；留空表示不限。

条件示例适用平台
最高租金€1200全部（见下方「各平台的租金口径」）
最小面积25 m²全部
最低楼层1Holland2Stay、OurDomain、OurCampus、Magis、Plaza
城市Eindhoven、Amsterdam全部
平台Holland2Stay、Xior全部
租客资格仅限学生除 Magis 外
房型Studio除 Xior 外
入住人数单人Holland2Stay、OurDomain、OurCampus
装修带家具Holland2Stay、OurDomain、Xior、Magis
合同无固定期限仅 Holland2Stay
最低能耗标签BHolland2Stay、Magis
片区、楼盘Centrum跟随所选城市
房源类型出租仅 Holland2Stay

平台不提供某个字段时，这条条件对该平台整体跳过，而不是把它的房源全部过滤掉。所以「最低能耗标签：B」并不代表你收到的都是 B 级：Xior、OurDomain 和 OurCampus 的房源根本没经过这一关。账号设置里每条条件旁都标着同样的适用范围。

平台显示的价格
Holland2Stay全包：含服务费和水电预付
Xior全包：基础租金加该楼每月预付费用
Magis全包：基础租金加每条房源标出的服务费

OurDomain 和 OurCampus 不说明哪一套对应哪档服务费，算不出全包价。它们的房源会在价格下方注明该楼的服务费区间，通知里也带同样的说明。给这两个平台设最高租金时请留出余量，或者用平台条件把它们分开。

自动预订与申请

由管理员在管理后台 → 用户 → 选中用户 → 自动预订里按用户设置。前提是通知已开启且至少有一种可用的接收方式。预订条件与通知条件相互独立。

Holland2Stay

符合条件的房源变为「可预订」时，FlatRadar 会登录该用户的 Holland2Stay 账号、预订房子、提交订单，并立刻把付款链接发过去。它不会付款：付款需要本人通过那个链接完成。

结果不确定时，该账号的自动预订会暂停。请到 Holland2Stay 查看订单，按需付款或取消，然后在用户设置里点已核实，恢复自动预订。

Plaza

FlatRadar 可以为符合条件的 Plaza 房源提交申请。填写 Plaza 用户名和密码，并打开默认关闭的自动申请开关。申请提交后立即生效。结果不确定时只暂停这个账号的这一条房源，到 Plaza 核对后点已核实，恢复该房源应征即可。

申请人档案

Xior 和 OurDomain 共用一份申请人档案（姓名、国籍、住址、学业、背景调查和证件）。每组都会显示还缺几项必填。背景调查必须由本人如实回答。

先用试运行。它会在提交前检查部分步骤，但不会真的下单或申请，也不保证真实提交一定成功。确认没问题、准备好真实下单时再关掉。

管理后台

在自己部署的站点上，管理员账号的侧栏里有管理后台：

  • 用户：所有账号、它们的渠道和已登录的 App；可以编辑、排序、发测试通知。
  • 公告：给所有开着通知的用户发一条消息。
  • 设置：轮询、高峰时段、平台、城市和楼盘。保存后会请监控重新加载，页面会显示是否已生效、哪些值被环境变量覆盖。
  • 客户端管理：App 会话和推送设备，可以撤销或停用。
  • 数据健康、日志查看、崩溃报告和系统信息：各平台的抓取状况、可搜索分级的日志、App 崩溃报告，以及启动或重启监控。

常见问题

看不到房源

  • 确认监控在运行：管理后台 → 系统信息。启动不了就看日志查看，或者 docker compose logs h2s。
  • 确认平台已启用、并在设置里选了它的城市或楼盘。
  • 数据健康会按平台显示最近一次成功的时间和失败原因。

收不到通知

打开账号设置。账号收不到任何通知时，那里会有一张清单指出缺的一步；清单消失就说明整条链路是通的。手动排查：

  • 账号是启用状态，通知开关已打开。
  • 至少有一种接收方式：填好信息的渠道，或已登录 App 的手机。
  • 用 FlatRadar 发信时，邮箱已经确认。
  • 发送测试通知会逐个渠道列出结果。

被 403 拦截

部分平台在 Cloudflare 后面，偶尔会拦截请求。先在日志里看是哪个平台、哪种错误（403 的原因不止一种），检查网络和代理，再给平台一段冷却时间。代理设置见部署文档。
