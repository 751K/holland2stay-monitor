# Future Plan / 未来规划

本文区分已实现的能力、v2.2 待完成的工作和未排期方向。版本历史见
[CHANGELOG.md](CHANGELOG.md)，当前架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

核对日期：2026-11-03。核对基线：v2.1.0 发布时的代码、测试、工作流及现有平台验证
记录。代码已实现、自动检查已通过和生产环境已验收分别记录，
不互相替代。

## 当前进度

v2.0.0 已发布，完成了监控管线整理、平台能力登记、配置快照与热重载、浏览器工作
进程、通知事件处理和预订结果不确定时的保护。项目继续采用单机 SQLite 与 Web /
monitor 双进程架构。

v2.1.0 按 Web 改版发布，变更见 [CHANGELOG.md](CHANGELOG.md)。原定在 v2.1 进行的
OurDomain、OurCampus 与 Xior 预订验证移到 v2.2。后续开发以实际验收问题、性能瓶颈
和明确的功能需求为依据。

### 已实现的 Web 能力

| 范围 | 当前实现 |
|---|---|
| 布局与导航 | 房源工作区和管理工作区使用统一的页面外壳与角色导航；页面提供响应式布局、中英文文案及浅色、暗色样式。 |
| 房源浏览 | 收件箱提供平台分组、搜索、筛选、分页和完整详情；普通用户可切换“我的匹配”与“全部房源”，个人已读状态独立保存。 |
| 日历、地图与统计 | 页面沿用当前浏览范围；日历提供入住日期分组，Google Maps 提供位置聚合与详情；日期和位置选择支持局部更新与浏览器前进、后退。 |
| 账号设置 | 普通用户按分组和条目编辑筛选、通知、账号及偏好；通知配置引导和测试入口集中在账号设置中，保存后保留所在条目。 |
| 用户管理与运行设置 | 管理员可以分组编辑用户、平台凭据和预订配置；运行设置区分已保存、已应用、被覆盖及需要重启的状态。 |
| 运维与公共页面 | 监控、日志、崩溃和系统信息页使用统一的管理导航；登录页已改版，帮助、使用指南和法律页面采用公共页面外壳。 |
| 本机启动与部署说明 | `python launcher.py` 支持准备浏览器内核、启动 Web 与监控，并清理自身启动的监控进程；文档区分本机使用和公网部署。 |

主要实现位于 [templates](../templates/)、[static](../static/) 和
[app/routes](../app/routes/)。[Web 冒烟测试](../tests/test_web_smoke.py)覆盖不同身份、
语言和主要页面入口；收件箱、账号、日历与地图另有行为测试。本地 Chromium 已完成三类身份的主要操作、响应式布局及
局部失败恢复检查，发现的问题已经修复并复测；尚未覆盖的范围见下方「Web 补验」。

## v2.2：待完成

### Web 补验

1. **真实设备与浏览器补验。** 本地 Chromium 已检查登录退出、个人条件保存、浏览范围、
   房源阅读、地图、日历、空结果及局部失败重试。后续需要检查 Safari、Firefox 和真实
   手机的触摸、软键盘行为；需要单独验证注册最终提交、密码修改和真实通知投递。
2. **布局与可访问性补验。** 本轮已检查桌面及窄屏、中英文与浅暗色的代表页面、键盘
   焦点和跨分组表单错误定位。后续仍需检查真实屏幕阅读器，并统一英文数量文案。
3. **回归保障。** 本轮已为关键服务端问题补充测试；侧栏焦点、局部重试和响应式行为
   尚依赖人工浏览器复测，应按维护需求补充必要的自动浏览器测试。
4. **部署与上线观察。** 分别验证本机首次启动和公网部署，确认监控启停、数据库迁移、
   既有配置与凭据保留，以及实际环境中的 Google Maps 加载。部署后观察每天执行的
   设备与 App 会话清理任务，并记录自动测试无法覆盖的运行限制。

### 平台与预订验证

Holland2Stay 预订链路与 Plaza 应征已有验证记录。当前只有这两个平台在
[SourceSpec](../mcore/sources.py) 中声明为可自动预订，Plaza 还需要用户单独启用。

OurDomain、OurCampus 与 Xior 的验证从 v2.1 移到 v2.2，Web 改版完成不代表这些链路
已经验证。各平台需要完成以下工作：

| 平台 | 已有记录与剩余验证 |
|---|---|
| OurCampus | 已走通选中单元、条款、开始申请及登录；登录后的 Applicant Info 流程尚未完成，需要重做后续填写和提交，并核实申请结果。开始申请不表示锁定房源。 |
| OurDomain | 已走通申请入口；登录后的填写、提交与结果确认需要真实账号验证。 |
| Xior | 已使用真实账号推进至申请表并保存草稿；证件保存和后续申请步骤仍需验证。草稿不表示锁定房源。 |

开工前先确定验证范围与完成标准。只有真实调用链满足平台对应的成功判据后，才能
更新平台能力登记或开放用户入口；不能仅凭存在 booker 实现认定平台已经可用。
平台资料见 [RENTCAFE.md](RENTCAFE.md)、[OURDOMAIN.md](OURDOMAIN.md) 和
[XIOR.md](XIOR.md)。

## 未排期方向

- **大数据量性能。** 先测量实际房源量下的筛选、计数、分页和地图聚合开销，再按瓶颈
  优化查询与渲染，不重复开发已经存在的分页和联动。
- **运维信息联动。** 当前管理页面已经统一导航与外壳；是否进一步关联平台异常、抓取
  轮次、日志和崩溃记录，需要依据实际排障流程确定。
- **管理 API。** 管理 API 当前支持用户列表、启停和删除；创建与编辑接口仍待明确需求。
- **统计扩展。** 平台之间的房源更新速度对比及健康指标扩展尚未排期，不与现有统计页
  的改版混为一项工作。
- **候选平台。** [SCRAPING_RECON.md](SCRAPING_RECON.md) 保存历史资料及待复核评估。
  新平台接入前需要重新核查规则、数据可用性、账号要求和维护成本。

上述方向在需求、范围和验收标准明确后，再安排具体版本。

## 实施约束

- 后续界面调整应保留已确认的鉴权、个人筛选与预订保护行为；需要改变 API、数据库
  schema 或监控行为时，必须单独记录并提供相应迁移与回归验证。
- 功能实现与第三方平台的真实验证分别记录；部署后的结果不能由本地 CI 状态代替。
- 页面行为发生变化时，同步维护受影响的测试、使用指南和 API 文档。
