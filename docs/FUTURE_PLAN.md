# Future Plan / 未来规划

本文记录尚未完成的工作、v2.0 发布前仍需确认的事项，以及 v2.1–v2.5 的方向。
已完成的设计与修复见 [CHANGELOG.md](CHANGELOG.md)，当前架构见
[ARCHITECTURE.md](ARCHITECTURE.md)。

> 核对范围：当前工作区代码、测试与工作流。「已实现」表示本地代码具备该能力，
> 不代表线上已复测。

## v2.0：当前进度

v2.0 侧重监控正确性、可维护性和回归保障，保持单机 SQLite 与 Web / monitor 双进程
架构，不以新增平台或客户端功能作为发布前提。

工程侧已收口：监控管线分阶段、`SourceSpec` 平台登记与调度、配置解析与热重载、
浏览器与预订工作进程、通知分发、存储层 SQL 归位，以及 Web 侧进程内限流的统一实现。
CI 在 push / PR 上运行 Ruff 与 pytest，并安装了 Node 以覆盖浏览器 JS 测试。

`dev/2.0.0` 已部署到生产；本次部署验证了进程启动、健康检查、数据库迁移与生产配置
保留。预订链路仍缺真实账号和房源下的端到端验证，见下。

## 尚未完成

### 平台与预订验证（移交 v2.1）

Holland2Stay 预订链路与 Plaza 应征均已验证。当前只有 Holland2Stay 与 Plaza 在
`SourceSpec` 中声明为可自动预订；Plaza 还需用户单独启用。不得仅凭存在 booker
实现就将平台标为已验证或自动开放。

OurDomain、OurCampus 与 Xior 的预订验证不属于 v2.0 发布阻塞项，统一放到 v2.1。
其中 OurCampus 需要重做登录后流程；Xior 与 OurDomain 的具体范围在开工前确定。

### 发布前确认

- 部署后观察设备 / App 会话清理任务（每天一次）是否正常运行。
- 确认真实调用链测试覆盖不到、但实际使用会遇到的限制，并记录下来。

### 可选，非 v2.0 承诺

- 管理 API 创建 / 编辑用户（当前只有列表、启停、删除）。
- 跨平台统计、房源更新速度对比、扩展健康看板。
- 未接入平台的候选与历史评估见 [SCRAPING_RECON.md](SCRAPING_RECON.md) 第 2 节，
  不构成排期；接入前需重新核查规则、数据可用性、账号要求与维护成本。

## v2.1–v2.5：Web 界面

v2.0 之后的重心转到 Web 面板；v2.1 另带 OurDomain、OurCampus 与 Xior 的预订验证。
以下按版本划分主题，具体页面范围在开工前再收窄；不在规划文档里写死组件级细节。

| 版本 | 主题 | 范围 |
|---|---|---|
| v2.1 | 页面骨架与导航 | 统一布局、导航与响应式；移动端可用；统一的加载、空状态与错误提示。同时包含 OurDomain、OurCampus 与 Xior 的预订验证（OurCampus 需重做登录后流程） |
| v2.2 | 房源浏览 | 列表、地图、日历的筛选与联动；排序与分页；大列表性能 |
| v2.3 | 设置与用户管理 | 设置页分组与生效状态；用户表单、凭据与自动预订配置；校验反馈 |
| v2.4 | 运维面板 | `/monitoring`、日志、崩溃与系统信息合并为一致的排障视图 |
| v2.5 | 视觉与可访问性 | 设计令牌、暗色模式一致性、键盘操作与可访问性、中英文文案收尾 |

约束：

- 界面改版不改变 API、数据库 schema 与抓取 / 预订行为；必须改动时单独记录并验证。
- 每个版本保留现有页面的行为测试与关键路由测试。
- 视觉方案确定后再补具体页面清单。
